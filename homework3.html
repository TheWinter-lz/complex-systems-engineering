0 · 作业概述

系统对象与作业目的

所选系统：面向高级别自动驾驶（L4/L5）的线控底盘平台（延续作业1的系统层对象、作业2的 BRS/StRS 分析结论）。本阶段进入方案域，从技术视角定义系统应具备的功能、性能与接口，并给出初始系统架构与安全方案。

作业目的：结合小组讨论与 AI 问答，进行系统需求分析及架构定义；参考第5章表 5-1（ISO/IEC/IEEE 29148:2018 SyRS 范例），输出系统需求规格书（SyRS）、初始系统架构、系统控制框图，以及安全需求与安全架构。

需求追溯链路：业务需求 BRS（作业2）→ 相关方需求 StRS（作业2）→ 系统需求 SyRS（本作业）→ 系统架构与设计 → 子系统/模块需求。系统需求是架构、设计、集成与验证的基础；在约束允许的前提下，系统需求只描述"系统要做什么"，不暗含具体实现方案。
1 · SyRS 系统需求规格说明书

系统需求规格说明（System Requirements Specification）

1.1 简介

目的：将作业2确定的相关方需求转换为技术视角、可度量的系统需求集，明确线控底盘平台应具备的功能、性能、接口与质量特性，作为架构定义与后续设计、验证的基线。

范围：覆盖线控转向、线控制动、线控驱动、底盘集成控制及其控制软硬件；不含上层感知、决策与规划算法。外部交互对象包括自动驾驶域控制器、整车供电与通信网络、执行子系统与传感器。

定义：SyRS（System Requirements Specification）系统需求规格说明书；FR 功能需求、PR 性能需求、IR 接口需求、QR 质量特性需求、SR 安全需求。

1.2 外部接口需求（IR）

编号接口方向接口对象接口需求描述
IR-01上游输入自动驾驶域控制器（ADS）接收规划轨迹、期望转向角/力矩、期望减速度/驱动力矩指令；反馈底盘状态与故障信息。
IR-02下游输出转向 / 制动 / 驱动执行子系统向下发执行控制指令，并采集各执行器位置、力矩、温度等反馈信号。
IR-03支撑接口整车电源 / 车载总线 / 诊断接口接入 12V/48V 冗余电源；通过 CAN/LIN/Ethernet 通信；支持诊断读取与故障码上报。

1.3 功能需求（FR）

编号功能需求描述追溯 StRS
FR-01接收并解析 ADS 下发的横纵向控制指令，进行指令有效性与合理性校验。REQ-02
FR-02实现线控转向控制：按期望转向角/力矩驱动转向执行器，并闭环反馈转角状态。REQ-02
FR-03实现线控制动控制：按期望减速度/制动力矩驱动制动执行器，实现车辆减速与驻车。REQ-02
FR-04实现线控驱动控制：按期望驱动力矩协调驱动执行器，提供加速与驱动力矩矢量分配。REQ-02
FR-05横纵向运动协调控制：综合转向、制动、驱动指令，维持车辆稳定性与轨迹跟踪。REQ-02 / REQ-04
FR-06状态监控与故障诊断：实时监控各通道、执行器与传感器状态，定位故障并生成故障码。REQ-03 / REQ-05
FR-07降级与最小风险控制：检测到故障时按规则降级运行，必要时进入减速、靠边、驻车的最小风险状态。REQ-03 / REQ-05

1.4 性能需求（PR）

编号性能指标需求指标要求验证准则
PR-01控制响应时延指令接收到执行输出的响应延迟 ≤ 10 ms台架/在环测试测量时延
PR-02轨迹/位置控制精度横向轨迹跟踪误差 ≤ 0.1 m整车场地测试与数据分析
PR-03系统可用性运行可用性 ≥ 99.999%可靠性统计与可用性分析
PR-04乘坐舒适性加速度及其变化率（jerk）限制在舒适区间，避免突兀动作客观指标测试 + 主观评价
PR-05闭环反馈周期状态采集与控制闭环按规定周期稳定执行，无丢失指令在环测试监视闭环周期与丢包率

1.5 质量特性需求（QR）

可靠性 / 可用性

  • 关键控制通道具备冗余设计，单点故障不导致完全失控；
  • 故障可被检测、隔离并提示，支持持续降级运行。

可维护性 / 可支持性

  • 支持自诊断、故障定位与维修引导，备件可达；
  • 具备远程状态监控与 OTA 迭代升级能力。

环境适应性

  • 适应车用温度、振动、湿度与电磁兼容环境；
  • 在规定环境范围内功能与性能不降级失效。

信息安全

  • 通信与控制指令具备防篡改、防劫持保护；
  • 关键操作与数据可追溯，满足车载信息安全要求。

1.6 设计约束

  • 功能安全约束：安全相关需求满足 ISO 26262 相应 ASIL 等级（最高按 ASIL-D 考量），预期功能安全参考 ISO 21448（SOTIF）。
  • 接口与标准约束：遵循统一的机械、电气与通信接口规范，兼容整车电子电气架构。
  • 资源约束：在既定成本、重量、功耗与进度范围内实现；需求不绑定单一供应商或单一实现方案。
2 · 初始系统架构

初始系统架构定义

架构定义：系统架构是系统在其环境中的基本概念与属性，以及组织组件、子系统使其紧密协同工作的结构、行为与设计决策。本架构将线控底盘平台划分为四个逻辑层次，明确功能映射与组件分工。

2.1 逻辑分层架构

层次组成组件主要职责
决策控制层底盘域控制器（VCU）、主控制 MCU、冗余监控 MCU指令解析、横纵向协调控制、策略决策、故障监控与冗余切换。
执行层线控转向子系统、线控制动子系统、线控驱动子系统执行转向、制动、驱动力矩输出，完成车辆横纵向运动。
感知反馈层转角/力矩传感器、轮速传感器、压力传感器、温度传感器采集执行状态与车辆运动状态，形成闭环反馈。
冗余与支撑层冗余电源、冗余通信通道、诊断与监控接口提供供电与通信冗余、自诊断、日志记录与对外接口。

2.2 功能—组件映射

  • 横纵向协调控制功能 → 决策控制层 VCU；
  • 转向/制动/驱动执行功能 → 执行层三个子系统；
  • 状态闭环与故障监测功能 → 感知反馈层 + 冗余监控 MCU；
  • 降级与最小风险策略 → 决策控制层调度，经执行层与冗余层协同完成。

4 · 安全需求与安全架构

安全分析、安全需求与安全架构

4.1 安全分析思路

基于初始系统架构开展系统理论过程分析：识别危险场景与潜在失效（执行器卡死、通信中断、传感器失效、电源失效等），分析失效后果与触发路径，据此导出安全需求，并在架构中落实相应的安全措施。

  • 危险识别：转向/制动/驱动失控、指令错误、状态反馈丢失、单点故障扩散；
  • 分析方法：故障树分析（FTA）自上而下追溯危险原因，失效模式与影响分析（FMEA）自下而上评估失效影响，结合冗余与监控思想进行安全架构设计；
  • 安全目标：任意单点故障不导致车辆不可控，故障后进入可控的安全状态。

4.2 安全需求清单（SR）

编号安全需求描述对应风险
SR-01关键控制通道与关键传感器采用冗余设计，主通道失效时冗余通道可接管。单点硬件失效
SR-02独立监控 MCU 对主控输出进行交叉校验，发现指令/状态不一致时触发安全响应。主控错误或失控
SR-03通信链路具备冗余与有效性校验，检测到通信中断或数据异常时进入降级策略。通信中断 / 数据被篡改
SR-04电源采用冗余供电，单路电源失效不影响基本安全功能。供电失效
SR-05故障发生后按"检测 → 隔离 → 降级 → 最小风险状态"流程响应：减速、靠边、驻车并上报。故障扩散导致事故
SR-06安全相关设计满足 ISO 26262 功能安全等级要求，关键事件完整记录可追溯。合规与责任界定

安全架构要点：主控与监控通道相互独立、冗余资源并行布置；安全措施覆盖感知、决策、执行、供电、通信各环节；任一环节失效时，系统由冗余通道维持基本可控，并最终进入最小风险状态，避免不可控后果。
5 · 追溯与小结

需求追溯与结论

追溯关系：本作业 SyRS 中的每条功能、性能与安全需求均可向上追溯至作业2的相关方需求（REQ-01～08），向下可分配至转向、制动、驱动等子系统需求；架构组件与安全措施对应相应需求条目，形成 BRS → StRS → SyRS → 架构/设计的完整追溯链。

小结：本作业将线控底盘平台的相关方需求转换为技术视角、可度量的系统需求集，明确了外部接口、功能、性能与质量特性约束；在此基础上给出四层初始系统架构、系统控制框图，并通过安全分析导出安全需求与双通道冗余安全架构，为后续系统设计、集成与验证提供基线。
